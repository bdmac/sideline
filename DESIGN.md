# Sideline design system

## Direction

Sideline is a calm magnetic tactics board translated into an operational match sheet. It deliberately avoids the generic analytics dashboard: the primary hierarchy is team identity, game state, pitch, bench, and the next action.

The physical scene is a coach using a phone outdoors in daylight or under field lights, often one-handed and under time pressure. The interface therefore uses high-contrast surfaces, explicit labels, large controls, and restrained color. Light mode remains the daylight-first default; a persistent header toggle switches to an intentionally inverted night palette on the local device.

Dark mode preserves the same semantic hierarchy rather than introducing a separate visual language:

| Token     | Value     | Dark-mode role                                     |
| --------- | --------- | -------------------------------------------------- |
| Ink       | `#dce9e5` | Soft mineral primary text and strong rules         |
| Paper     | `#0d191b` | Blue-green near-black main surface                 |
| Wash      | `#17272a` | Raised and inactive surface                        |
| Turf      | `#35b7a2` | Primary action and current state                   |
| Turf pale | `#153a35` | Selected and resumed-state background              |
| Warm      | `#e8763f` | Substitution action                                |
| Warm pale | `#40251b` | Substitution notice background                     |
| Danger    | `#df6464` | Destructive action                                 |
| Focus     | `#79bfff` | Visible keyboard focus against near-black surfaces |

Dark surfaces use two restrained rule levels: `#293a3c` for ordinary list dividers and `#455c5e` for 2px structural boundaries such as dialog headers, footers, and major section breaks. The top edge of dialogs and mobile action sheets is a separate, quieter 3px `#33484a` rule so it frames the surface without flashing against the backdrop. Strong boundaries no longer borrow the primary text color.

Outlined controls use a separate neutral slate border (`#5d696e`, rising to `#818e92` on hover) rather than borrowing primary ink. This keeps secondary actions, steppers, and field controls present without producing bright white boxes in dark mode.

Filled controls use deeper night-enamel variants of the semantic colors—turf `#14766b`, substitution `#a94620`, and danger `#a63f43`—with softened `#f1f5f3` text. This preserves the familiar light-on-color control treatment and AA contrast without dimming accent text or operational borders elsewhere.

Color never communicates state alone. Text such as “Present,” “Clock paused,” “OUT,” and “IN” remains visible.

## Typography

Use one practical system sans stack: `Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`. Headings use compact negative tracking and heavy weights. Timers use tabular numerals. Labels remain sentence case; small uppercase is reserved for position codes and substitution direction.

## Composition

- Main configuration screens use a single centered ledger column, not nested card grids.
- Ruled dividers structure lists and sections.
- Team age badges and pitch position tags behave like removable tactics-board magnets.
- The Sideline mark shows a ball crossing a touchline, combining the match setting with a small flash of substitution orange.
- The top-right header actions contain adjacent 44px Primer `IconButton`s for light/dark mode and settings. The settings cog opens a conventional anchored Primer ActionMenu in every viewport; it never becomes a bottom sheet. Two clearly explained Primer `ToggleSwitch` controls manage screen wake lock and substitution chime/vibration. Both choices are stored separately from game data so they persist without affecting game-state migrations.
- Golden Dragons use a gold-and-turf shield with a bold, front-facing heraldic dragon head: hooked swept horns, an armored brow, a tapered muzzle, and narrow gold negative-space eyes stay unmistakable at header size, while a centered U8 label occupies the clear gold crown above the emblem. Fireballers use an ink shield with an orange flame and ball. Team crests identify squads without replacing text labels.
- The live game expands to a two-column pitch/bench workspace on larger screens and a single scan path on phones.
- Full pitch views read bottom-to-top from the team’s defending goal toward the attacking end. Subtle Attack/Defend labels make that orientation explicit, and formation coordinates keep forwards outside the penalty-area edge while preserving recognizable defensive, midfield, and attacking lines.
- New-game setup uses a linear sequence of three focused panels—Attendance, Formation, and Starters—with one compact current-step progress indicator in the header and persistent destination-labeled Primer controls (for example, Formation or Starters) instead of cramped tabs or one long scrolling form. The fixed mobile footer preserves the standard default and primary button treatments with leading/trailing directional visuals rather than replacing them with custom icon badges. The toolbar contains navigation only and does not repeat progress. Backward and forward controls share the same structure. Attendance remains a two-column touch grid on phones to minimize vertical travel.
- The Starters step reuses the pitch as the primary assignment surface. Large position magnets open a bottom-sheet player picker, and the derived starting bench is shown as a compact name tray below the field.
- Critical live controls sit inside an opaque, edge-to-edge bottom surface with safe-area padding and four equal-width Primer buttons. Content never shows through or around the navigation surface while scrolling.
- The game clock remains sticky below the app header on phones.
- The Game in progress strip on team selection shares the live game’s one-second clock cadence, including accurate paused and added-time states.

## Controls

- Minimum interactive target: 44px; critical controls are 50–66px.
- Conventional commands use Primer `Button` and `IconButton` primitives so focus, disabled, icon, and touch behavior stay consistent. Lucide icons are passed through Primer's `leadingVisual`, `trailingVisual`, and `icon` APIs; Sideline classes retain the established turf, warm, danger, sizing, and layout language. Purpose-built selection surfaces—team rows, attendance tiles, formation cards, tabs, score controls, pitch magnets, player choices, and numeric steppers—remain semantic native buttons because their geometry and state model are not conventional button chrome.
- Buttons are square or minimally softened by default. On phones, setup commands use fixed, edge-to-edge bottom surfaces with borderless tap areas, while live controls use large invisible-variant Primer buttons within the same safe-area-aware dock; page content reserves the toolbar height exactly once. Every bottom sheet spans the full viewport width regardless of its desktop maximum, while dialog task and confirmation actions retain the squared, tactics-board button treatment.
- Conventional actions stay within Primer’s default, primary, and danger hierarchy. Primary actions use turf; warm orange is reserved for substitution state, warnings, and directional emphasis rather than a separate button variant.
- A successful substitution opens a compact staging sheet with strong OUT / IN direction, Primer `Label` jersey numbers (`danger` for OUT and `success` for IN), and the affected position; numbers stay out of routine live screens to preserve scan speed, while attendance reuses the same semantic pair—success when present, danger when absent—during pregame confirmation.
- Planned substitutions use shared OUT / IN column headings rather than repeating direction labels in every row. Compact ActionMenu triggers keep editable rows terse—player names only—then reveal richer context when opened. A sticky “Who’s coming OUT?” or “Who’s going IN?” menu header preserves orientation on the mobile bottom-docked surface; IN headers also name the outgoing player and destination position. OUT options show current stint, total playing time, and position. IN options show current bench stint, total playing time, jersey number, and a separate preferred-roles line because role fit matters when choosing who enters. These menus remain anchored to their trigger on larger screens and become consistent bottom-docked selection surfaces on phones, keeping choices within thumb reach while preserving the menu’s selection semantics. While one player menu is open, the first tap on another selector dismisses the active menu without opening a replacement; a second deliberate tap opens the new selector. OUT options surface the players most due for a break first, while IN options surface the least-played and longest-waiting players first. An on-field player already selected OUT in another row is omitted because that player cannot be selected twice and the pairing remains visible in the planner itself. Every benched player remains selectable in every IN menu: players already assigned to another row move below all unplanned choices without disturbing fairness order, and choosing one pins that choice, clears only the row that previously held it, and reruns the normal recommendation for that one row against currently unassigned bench players. Every other planned row remains untouched. A separate warm status line identifies the current pairing as **Going in for [player]**. When the full bench is already included, the displaced player is necessarily the only available refill; with spare players, the fairest eligible candidate may be selected instead. Editable rows retain the crossed-arrows substitution symbol grouped with the affected position between the columns. The compact confirmation keeps each row shallow by placing the position code immediately after the arrow and right-aligning incoming names against the IN edge; ready-plan review returns to a vertical arrow/position grouping and a more spacious staging rhythm with jersey-numbered names. A ready swap follows its outgoing player when that player changes position, so the displayed position stays current without changing either selected player; undo restores the previous planned position. Each ready-review row can be removed independently: a visible danger icon is used for fine-pointer layouts regardless of viewport width, while a left swipe reveals the same action on narrow coarse-pointer devices. Keyboard focus also reveals the tucked action. Removal shrinks the plan rather than auto-filling an empty row, and removing the final row dismisses the plan. A warm, high-visibility live-game banner makes the ready state persistent without obscuring the pitch, and exposes separate **Review** and **Send 'em in** actions.
- When the team-specific interval passes without a completed substitution—12.5% of configured duration for U8 and 25% for U12—the same warm operational banner language prompts the coach to consider substitutions and offers one direct Plan subs action. It remains non-modal, disappears while a plan is ready, resets only when an OUT/IN change actually reaches the field (including an automatic replacement), and yields to both active added-time prompts and paused period-break banners. Those higher-priority surfaces retain Plan subs or ready-plan review so the capability never disappears.
- Bench rows pair the existing Take out of game control with a compact Primer primary icon action: the same swap-arrows symbol used by **Plan subs** adds a new entry to the plan, while pencil edits an existing one. The 44px filled control uses Primer’s primary variant without an additional icon color or ready-state override. Accessible names and focused-picker titles explicitly identify the bench player as going **in**. Players already included in the plan gain a turf-green row treatment and explicit destination status such as **“Going in at GK,”** matching the established IN language. The shared player-context surface uses Primer’s custom-content `Card` with condensed padding, a medium radius, a complete turf-colored boundary, and no shadow. Its semantic `<dl>` remains a responsive fact grid rather than a vertical stack: bench variants separate **Bench stint** and **Playing total**, while on-field variants separate **Position**, **Playing total**, and **Field stint**. Every time inside these context cards and their selectable player rows uses compact player-duration formatting: second precision below one minute and rounded minute precision thereafter, so an open decision surface stays visually calm. A zero lifetime total becomes **Not played yet**; active stint timers retain `0:00` so paused and pre-start states remain truthful and the value naturally counts up when play resumes. Focused plan-in, plan-out, and change-position candidates share two quiet aligned lines: player identity opposite role preference or destination position, then compact labeled timing. Plan-in keeps current position at the left of **Stint / Total**; plan-out places a typographically distinct **PREFERS** micro-label and role value opposite **Bench / Played**. One role remains fully named; multiple roles use compact **GK / DEF / MID / FWD** values with full names preserved for assistive technology. Occupied change-position choices use **Stint / Total**, while open destinations retain only the explicit **Unoccupied position** state. Ordinal preference matches retain turf emphasis; the neutral **Outside preferences** label replaces the ambiguous “Other role” and uses subdued ink rather than positive green. After a Change positions destination is selected, the Card's Position fact previews **current full label ⇄ destination code** with a compact turf arrow; the accessible label states both full positions. Before selection, the disabled footer instructs **Choose a position**; afterward it names the exact **Swap with…** or **Move to…** result. Row boundaries supply the structure, with no nested divider or table-like heading band. Preferred roles and the existing **Next rotation** pairing occupy the same scan-friendly grid and naturally collapse when the container is too narrow. Plan-out pickers expose the same next-rotation metadata. Focused plan-in and plan-out pickers mirror the position editor’s select-then-confirm model: row taps only update the preview and selected treatment, while a check-marked **Add to plan**, **Update plan**, or selected position action commits the state. The header X owns cancellation, avoiding a redundant footer button. Existing plans pair Update with **Remove from plan**; the actions stack on narrow phones rather than truncating. In both picker variants, the chosen replacement row uses a checkmark, turf surface, structural inset, and `aria-pressed` rather than relying on the subtle hover wash alone.
- Individual-player dialog headers own identity and preserve navigation continuity: the plain jersey-numbered name leads, with deeper tasks following after a hyphen—**#10 Simon**, **#10 Simon - Plan out**, **#10 Simon - Change position**. Goal markers stay in player rows and content rather than entering the title hierarchy. Context Cards begin directly with position and timing facts, avoiding a duplicated Player field and keeping all focused dialogs structurally consistent.
- When that focused picker is editing an existing ready player, it includes a clearly labeled outlined-danger **“Remove from plan”** action. This removes only that player’s pending swap and preserves the rest of the ready batch.
- The focused bench-player picker has a compact constrained viewport: its header and preference context remain fixed, roughly five replacement choices fit in an independently scrolling region, and the remove action stays pinned in a dedicated footer.
- Selecting a replacement from the focused bench-player picker closes directly back to the live game rather than forcing the ready-plan review sheet. The green ready row state and persistent ready banner provide immediate confirmation while preserving the coach’s bench-by-bench planning rhythm.
- Preference-fit labels use compact, softly filled rectangular tags: turf for first preference, muted gold for second, orange for third, rust for fourth, and danger red for outside preferences. The ordinal or explicit outside-preferences copy remains present for non-color-dependent meaning, and the restrained fills keep the row hierarchy calmer than saturated status badges.
- The multi-substitution ActionMenu rows mirror the focused picker grammar rather than maintaining a separate compact format: numbered identity and rank tint lead; OUT rows pair position with Stint / Total, while IN rows pair the PREFERS micro-label with Bench / Played. OUT players already committed in another batch row are omitted instead of consuming space as faded non-actions. Selected ActionMenu rows use the same horizontally inset but vertically flush turf surface, left accent, and check inside the preference tag as focused pickers rather than Primer’s default gray row and separate selection gutter; hover and keyboard focus preserve that treatment. Across multi and focused pickers, **Going in for [player]** uses turf green with reverse arrows while **Going out for [player]** retains the warm OUT treatment, preserving direction consistently even when choosing the row transfers an existing pairing.
- In ready-plan review, the top-right X only dismisses the sheet. Removing the plan is instead labeled “Delete plan,” uses a filled danger treatment with a trash icon, and requires explicit confirmation so it cannot be mistaken for closing the view.
- A compact scoreboard sits directly below the game clock. Its separator occupies the same value row as both score numerals rather than floating between the labels and values. Match-level Start/Pause/Resume and End game controls are adjacent in the expanded header. Both retain icon-plus-label treatment there; on phones only the destructive label contracts from **End game** to **End** while the team name yields space through ellipsis. The collapsed header reduces the same actions to adjacent 44px Play/Pause and flag controls. Their proximity makes the running-game lifecycle one coherent cluster while preserving danger emphasis for End game. The persistent mobile dock contains exactly three equal neutral controls ordered **Undo**, **Plan subs**, and **Goal**, placing substitutions in the center. During a period break, both the header and the break banner say **Start Q/H** for the upcoming period; **Resume** is reserved for a period that has already begun and was manually paused. Goal entry is disabled whenever the materialized game clock is stopped, while the score numerals remain available for reviewing scorer history. Position editing is removed from the dock because every pitch magnet is already its direct entry point.
- The own-team number in both expanded and compact score headers is a large, explicit touch target. It opens a quiet scorer ledger using the same amber ball markers as the final game summary.
- The live match status uses two expanded tiers: team identity with adjacent match controls, then a normalized clock/score/period row. The large clock counts upward within the current quarter or half and is led by a simple clock glyph rather than a redundant “Clock running” badge; the adjacent Start/Pause/Resume control already states the clock condition in words. The period column shows time left in that period and keeps total regulation remaining as quiet desktop-only context. As this header scrolls away on phones, a separate compact row fades and slides into place with team, a minimal `Q1 / 4` or `H1 / 2` marker, the same clock-glyph-plus-elapsed treatment at reduced scale, score, and adjacent match controls. The ordinary period countdown is omitted from this constrained row; only exceptional added time introduces a secondary `+m:ss added` line and warms the clock glyph. Reversing the scroll naturally restores the expanded header without layout snapping.
- Reaching a period’s regulation target surfaces a full-width operational banner immediately below match status without stopping play. A warm treatment distinguishes active added time; the copy shows a live `+m:ss` value and explicitly states whether the clock is running or manually paused. The expanded period metric and compact sticky header also expose added time, keeping it visible after the main banner scrolls away. Intermediate prompts pair substitution review/planning with **End Quarter/Half**; final regulation uses danger emphasis and the shared finish-flag icon for **End game**. The regular reminder and ready banners yield to this surface, while their relevant actions and ready count move into it.
- Ending an intermediate period materializes all time and creates the existing turf-tinted paused break banner. It shows the actual endpoint and added time, retains substitution review/planning, and makes **Start Quarter/Half** the deliberate primary action. During this break, the dock clock action reads **Resume Q/H** and resumes the same period, providing a fast recovery path if play restarts or the period was ended accidentally. Starting the next period advances the period state and gives it a full configured regulation interval from the actual restart.
- Short-sided attendance uses the danger color on both visible counts plus a bordered text alert, so the state never depends on color alone.
- Attendance tiles place a compact Primer jersey-number `Label` beside the player name, using success for present and danger for absent without changing the full-tile touch target.
- A dedicated **Guest players** section follows the permanent roster grid. A 44px Primer default plus button sits beside the guest count, keeping addition continuously available without giving a secondary setup action undue visual weight. It remains available whether the team is short-sided or simply needs more substitutes; the short-sided alert only communicates the shortage. Added guest tiles remain in this same temporary section and are always presented as present rather than duplicating the permanent roster’s attendance toggle. Removal is the sole undo action before kickoff, rendered as an overlaid, borderless Primer invisible IconButton whose 44px touch target is visually reduced to the danger-colored trash glyph and hover feedback. The entry sheet asks only for name and optional jersey number.
- During live play, a full-width borderless Primer invisible guest utility forms the final ruled row of the bench list. It mirrors a normal 76px player row, placing a plain plus glyph inside the same dark square normally used for a jersey number, followed by **New player** identity and an **Add to bench** secondary line. The invitation reads as an intentional blank roster entry rather than a detached button. The same row follows the empty-bench message, opens the shared guest sheet, and adds the player directly to the bench; open pitch positions retain their more direct add-and-field shortcut.
- A complete but undersized starter assignment changes the final setup action to “Start short-sided” and presents a calm confirmation explaining the player count before entering the live game.
- In a short-sided live game, an empty dashed pitch magnet is an actionable “Open” position. Tapping it opens the guest-player sheet and places the new guest directly into that role without a separate assignment step.
- The live Out of game list uses the same collapsed disclosure language as the game timeline. Its summary neutrally describes players as not currently available to play and keeps the count visible, while the infrequent Add to game controls stay out of the primary sideline scan path.
- The expanded game timeline uses a fixed icon column across every row: clock for period transitions, flag for Game ended, reverse arrows for substitutions, four-way Move for position changes, the Sideline soccer ball for either goal direction, plus for returning players, and player-out for unavailable players. Icons are decorative reinforcements beside explicit text, never the sole event signal. Quiet full-width period dividers carry the actual whole-game timestamp, a strong **Quarter/Half started** or **Game ended** label, and the preceding period’s endpoint with `+m:ss added time` when applicable. The wash surface and stronger horizontal rule make these structural markers scannable without making them look like undoable events.
- Bench rows use progressive disclosure: identity and played history lead, while timing follows an exceptions-first rule. Two or more players who have all sat since kickoff share one exact cohort timer above the list; their duplicate row timers disappear, while any player with a divergent bench stint receives a compact individual timer. Individual player values use familiar `m:ss` notation below one minute and rounded values such as `4 min` afterward, so the main game clock remains the only continuously changing minute-and-second display once a stint passes its first minute. A player with no field time reads “Not played yet.” One secondary-status line beneath the history conditionally shows **Going in at [position] for [player]**, the warm “Below 50% pace” warning, or distinct total bench time in that priority order. Planned bench and on-field statuses use the established reverse-arrows substitution icon and name both sides of the exchange so the coach need not search the pitch or reopen the picker. Checkmarks remain reserved for selection and confirmation. Aggregate time never stacks beneath the live timer, and competing statuses never display together. Plan/edit and Take out of game remain visible as separate 44px actions because hiding a single secondary action would add friction without simplifying the row.
- The live roster rail uses a two-tab Bench / On field switcher with counts, a turf underline for the selected tab, semantic tab keyboard behavior, and horizontal swipe navigation. Bench occupies the left, primary position and remains the default. Guest addition sits below the bench content so the tabs remain dedicated to switching views. When substitutes exist, a quiet Rotation utility row above both tabs presents the action-oriented “Due in” countdown until the next reminder, changing to “Due now” at the threshold. Keeping this metric outside the tab labels preserves identical tab geometry and keeps it visible in either roster view. On-field rows mirror the bench geometry and initially suppress timing while every current stint equals the main game clock. Once any stint diverges, all on-field rows show comparable numeric timing. Plan stays direct, while a genuine two-item More sheet groups Change positions and Take out of game. A planned on-field player reads **Coming out for [player]**. Tapping the same player on the pitch opens a shared context panel for position, playing time, and next-rotation status, followed by three distinct equal-width Primer buttons matching the proven ready-plan footer. The destructive **Take out** action anchors the left, neutral **Positions** sits in the middle, and the direction-aware **Plan out** action anchors the right with the turf-primary treatment; bench-player entry points use **Plan in**. Confirmation still separates destructive intent from applying the change. Every substitution action retains the shared crossed-arrows symbol used by the live dock and player lists, while Change positions uses a distinct four-direction Move icon.
- Soccer-ball markers follow scorer names on pitch magnets and across roomy in-game lists and sheets. One or two goals use individual balls, exactly three use three hatted balls, and larger totals use one hatted ball plus a compact exact count.
- The same soccer-ball glyph leads the live Goal and Opponent scored actions. Individual scorer choices omit a leading action icon so any soccer balls inside a player row have one unambiguous meaning: goals already scored.
- Record-a-goal choices retain the two-column button grid and place the current position code in a compact neutral Primer Label at the far edge of each button. The boundary prevents the code from visually merging with the player name, and the accessible name exposes the full position label. This constrained surface compresses hat tricks to one hatted ball plus `×3`; the player-name segment can ellipsize before either the goal total or position Label overflows.
- Every End game action uses the same finish-flag icon. On phones, the expanded action uses standard Primer danger styling, while the collapsed header reduces it to a flag `IconButton` to protect space while retaining a 44px touch target, an explicit accessible name, and a tooltip. The final confirmation keeps **End game** as the filled danger action, pairs it with the default **Continue game** safe action, and includes the standard header close button; Continue, close, Escape, and backdrop dismissal are equivalent.
- After end confirmation, a dedicated full-height game-summary page resets to the top, leads with the final score, and uses a ruled roster ledger sorted with scorers first and then by playing time. Each player has one bold total followed by plain position/time rows, with a direct zero-time message for players who never entered. Scorers receive one small soccer-ball marker per goal beside their name; goal positions and exact times stay in the game timeline to keep the player ledger calm. The collapsed game-timeline disclosure follows the roster ledger, and a sticky footer provides the single return action without covering report content.
- PWA installation appears as a full-width turf-tinted action beneath team selection, visible only while running in a browser.
- Form controls use white fill, dark text, and a visible 1px neutral border.
- Focus uses a 3px blue outline with offset.
- Disabled controls retain their label and use reduced opacity.

## Pitch

The pitch is the signature surface. It uses real field markings and restrained mowing stripes. Occupied player magnets use a stable two-row layout with a compact metadata rail at the top and the player name centered beneath. Position remains at top left; once any total diverges, playing time remains at top right using the same compact seconds/minute notation as roster rows. A warm reverse-arrows icon appears immediately beside the position code when that player has a pending substitution, preserving the timer while making the next rotation visible at a glance. The redundant “played” label remains omitted inside the magnet. Slightly wider responsive magnets accommodate scorer markers without crowding adjacent 9v9 positions. Nearby helper copy explicitly calls out tap-for-actions and drag-to-swap. A tap opens a player-scoped action sheet with the shared player-context panel and the Plan out / Positions / Take out rail; the subsequent position editor reuses the complete on-field context—position, playing total, field stint, and conditional next rotation—above the same large, scrollable player-choice rows used by substitution sheets. Occupied destination rows use jersey-numbered names plus playing total and current field stint, with the destination position aligned opposite; open destinations explicitly read **Unoccupied position**. Selection uses the same checkmark and turf treatment as focused substitution choices. The rows omit redundant Swap/Move copy. The footer begins as disabled **Choose a position**, then becomes the exact concise operation—**Swap with [player]** or **Move to [position code]**—with a fully explicit accessible name. Empty required positions use a dashed magnet and the word “Open,” making short-sided or injury states impossible to miss.

## Motion and accessibility

The product uses no decorative animation. State changes are immediate. `prefers-reduced-motion` reduces all transitions and animation durations. Semantic headings, labels, buttons, pressed states, dialogs, alerts, keyboard focus, and a skip link are included. Text and controls target WCAG AA contrast.

Every modal surface uses a shared Sideline shell backed by Primer Dialog. Dialogs are centered on larger screens and bottom-aligned at full width on phones, with fixed Sideline-styled headers and action footers around one independently scrolling body. A deep translucent ink backdrop clearly separates the active task from the paused game without hiding useful context. Primer owns focus trapping and restoration, Escape and backdrop dismissal, document scroll locking, viewport constraints, and nested-menu layering. Destructive alert dialogs normally omit the close button when cancellation already has task-specific meaning; the End game confirmation intentionally includes it because continuing the game is an unambiguous safe default, and every dismissal path is equivalent to that action. The Plan substitutions dialog is capped at 84% of the viewport so live-game context remains visible; other dialogs use a 92% ceiling so long player lists remain reachable without background drift.

## Responsive rules

- At 760px, pitch and bench stack; the clock becomes sticky.
- At 520px, attendance becomes one column and setup assignments stack their select. Substitution rows retain the desktop OUT ↔ IN sequence using constrained selector columns, compact option text, and a visible directional icon.
- No critical action depends on hover.
