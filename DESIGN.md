# Sideline design system

## Direction

Use **Substitution plan** for the editable queued changes, **In this plan** for player-context facts, and **Next reminder** for timing. The planner title introduces the full term; ready review retains the count as **Substitution plan (N)**. **Create plan** starts planning, **Add to plan / Update plan** edit it, and **Send 'em in** executes the reviewed changes.

One planner combines suggested swaps with coach-controlled replacement selection; Settings has no Manual mode switch. Opening without a saved plan starts with recommendations, while saved pairings remain intact. Bench dragging stages swaps instead of executing them. The swap list ends with a compact add row: **Swap another player. N left on bench.** on the left, and a 44px invisible `UserRoundPlus` icon button on the right, aligned with the row removal actions. N is the bench count minus the number of draft rows. Removing a row restores that slot; changing players does not change the count. The icon uses teal foreground and a pale turf hover; its tooltip and accessible name are **Add swap**. It inserts one suggested pairing without changing existing rows and focuses the incoming picker, or another enabled row control when that identity is read-only. The add row disappears when no bench/outgoing slot remains, including keeper-handoff reservations. Rotation deadlines use the guarded automatic review/planner behavior. Injury removal always uses the shared bench replacement list, advisory preference/keeper notices, and a disabled confirmation until a required replacement is chosen.

The add-row helper says **Swap a player.** with zero draft rows, then **Swap another player.** as soon as a row is added. Both states retain the remaining bench count.

**Take out of game** replacement selection shares the **Plan out** bench list rather than a native dropdown: large selectable rows show player identity, position fit, preferred roles, bench/playing time, and saved-plan status. Both surfaces share fairness ordering with already-planned players grouped last under **Already going in**. In narrow containers, preferred roles and timing occupy separate full-width rows to avoid overlap. No replacement is preselected for removal; selection previews warnings and affected pairings without changing the game. **Keep player** cancels, while **Remove player** explicitly marks the outgoing player unavailable and sends the chosen replacement on immediately. Warnings and plan-impact copy stay with the confirmation footer, separate from the scrollable choices.

The planner uses the bottom add row and per-row removal treatment, without a **Players to swap** selector. Existing rows never reshuffle just because a row is added or removed. Removing the final row shows **Clear plan** for an existing saved plan and disabled **Choose a swap** for a new empty draft.

The drag preview retains its original fixed-height header so drop targets do not move as warnings appear. It omits routine “Adds to plan” helper copy. The single notice slot prioritizes keeper warnings over brief plan-conflict hints. Drops update ordinary pairings directly; linked keeper conflicts open the full editor. The instruction always says **Drop on a player to plan [name]'s swap.** Immediate substitutions remain under **Sub now**, with confirmation only for a conflicting saved keeper handoff. No additional status panel is introduced.

The planner keeps **Optimize plan** as a compact 44px `WandSparkles` IconButton beside Close on every screen size, with one Primer label tooltip and no browser title. Tapping rebuilds only the draft immediately, without a modal. The existing header description changes from **Choose your swaps, then save the plan…** to **Rebuilt with N suggested swaps for fair playing time. Save the plan when you're ready.** This single polite live region provides visible feedback without another row, helper paragraph, or duplicated announcement. Editing a pairing, adding/removing a row, or reopening the planner restores its normal description. The wand is disabled when recommendations already match or no rotations remain; editing the draft re-enables it when recommendations would change it. Save plan persists the draft and Send 'em in still executes. The deterministic algorithm compares all pairing and keeper-handoff details independently of row order; no artificial delay or AI-service claim is added.

During bench dragging, queued arrivals appear beneath each affected position's current player, with the warm substitution icon and the incoming name. Compact cards retain their existing target size and position; tighter internal spacing accommodates the extra line. Names ellipsize when needed while accessible labels and titles retain the full name. An on-field keeper arrival uses the distinct Move icon, and its vacated position shows the true bench replacement. Desktop pitch cards expose the same arrival details only during the drag, preserving the normal live-pitch presentation afterward. Hovering a different target never replaces these saved-plan names with the dragged player's name.

Plan-in player details use the position scan label in **In this plan** (for example, **Center Back** or **Left Mid**) rather than the shortcode. This applies to both existing pairings and selection previews; compact live bench statuses retain their shortcodes.

Focused planning cards align their facts: **Positions** (Plan in) or **Current Position** (Plan out) leads at the top left, with **Sitting now** or **Playing now** directly below. **Played** and **Goals** occupy the right column. DOM order follows that same row-by-row reading order.

Player-context values use 500-weight normal ink, including **No goals… yet!**; small labels and spacing supply the hierarchy rather than extra-bold values or a muted empty-state exception. In focused pickers, In this plan uses the standard context label above that same treatment for both the pairing and its consequences. Consequences inherit the pairing's size and weight rather than introducing a second alert style; the pairing itself no longer uses warm alert text.

Focused planning lists group every player with a saved substitution—including the current pairing being edited—under a centered **Already going in** heading for bench choices (Plan out), or **Already going out** for field choices (Plan in), on a neutral wash and a strong top rule. The smaller centered helper **Already included in the plan.** fits on one line. After selection, the In this plan fact names any players who will lose their planned swap and where they remain: **This leaves [names] on the field and [names] on the bench.** Empty groups are omitted. This is a preview, announced as a status, not an immediate change. Its impact calculation is shared with the save operation. This makes the existing scheduled-last ordering visible before the coach scans preference badges. Pairing details stay in each row; rows retain full contrast, normal selection behavior, and keyboard access. Group membership follows the saved plan, not the current draft selection, so previewing another choice does not move the existing pairing outside its group.

The full planner's IN / OUT action menus use the same separator, grouping players already assigned in the current editor draft, including the edited row's selection. The separator shares the player rows' half-rem side gutters; it has no extra group gap and its helper uses normal weight. Primer's semantic menu groups preserve keyboard navigation and expose the group name without making the separator selectable. Empty groups are omitted.

Editor and review row numbers share the same neutral gray rectangular badge, centered numeral, weight, and responsive dimensions.

In the full planner, already-planned IN options use Primer's disabled menu-item semantics and styling without an extra opacity fade, retaining their names and scheduled-pairing details. The current selection is also disabled but retains its checkmark and highlight. Pointer and keyboard input cannot transfer a reserved IN player; editing or deleting the reserving row releases them. OUT options retain their existing reassignment behavior. Focused **Plan out** keeps all incoming rows selectable because it also offers **Sub now**, but disables Add/Update plan for an IN player reserved elsewhere. An explanation beside the actions names the existing pairing and directs the coach to edit/remove it or use Sub now. Such previews use **Selected swap / Would come off for**, not a claim that the change is already planned. Injury removal remains unrestricted.

When a selected player has no enabled alternative, the picker is replaced with a review-style, full-contrast name and jersey number: no button border, chevron, or disabled fade. Player choices remain vertically centered in their rows, including these shorter read-only identities. This follows the actual option set, not row capacity: keeper-limited plans can still have valid IN choices even with Add hidden. Releasing a reservation restores the picker. If filling the last slot makes a picker read-only, focus moves to an enabled control in that row rather than disappearing with the picker or Add button.

Sideline is a calm magnetic tactics board translated into an operational match sheet. It deliberately avoids the generic analytics dashboard: the primary hierarchy is team identity, game state, pitch, bench, and the next action.

The physical scene is a coach using a phone outdoors in daylight or under field lights, often one-handed and under time pressure. The interface therefore uses high-contrast surfaces, explicit labels, large controls, and restrained color. Light mode remains the daylight-first default; a persistent header toggle switches to an intentionally inverted night palette on the local device.

Dark surfaces use two restrained rule levels: `#293a3c` for ordinary list dividers and `#455c5e` for 2px structural boundaries such as dialog headers, footers, and major section breaks. The top edge of dialogs and mobile action sheets is a separate, quieter 3px `#33484a` rule so it frames the surface without flashing against the backdrop. Strong boundaries no longer borrow the primary text color.

Outlined controls use a separate neutral slate border (`#5d696e`, rising to `#818e92` on hover) rather than borrowing primary ink. This keeps secondary actions, steppers, and field controls present without producing bright white boxes in dark mode.

Filled controls use deeper night-enamel variants of the semantic colors—turf `#14766b`, substitution `#a94620`, and danger `#a63f43`—with softened `#f1f5f3` text. This preserves the familiar light-on-color control treatment and AA contrast without dimming accent text or operational borders elsewhere.

Color never communicates state alone. Text such as “Present,” “Clock paused,” “OUT,” and “IN” remains visible.

## Typography

Use one practical system sans stack: `Inter, ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`. Headings use compact negative tracking and heavy weights. Timers use tabular numerals. Labels remain sentence case; small uppercase is reserved for position codes and substitution direction.

Mobile operational text follows an outdoor-readability floor rather than shrinking uniformly to preserve density: primary body and input text remains 16px or larger; player names remain at least 16px; critical mobile action labels are 14px; pitch timing, scoreboard labels, period state, attendance numbers, and settings support copy stay roughly 12–13px. Smaller lettering is reserved for redundant crest details and formation-diagram abbreviations. Tight surfaces retain single-line labels through existing nowrap, ellipsis, and compact-copy behavior rather than reducing critical text again.

The collapsed live header uses a compact, content-sized score column between two equal flexible panels: the existing 30px mini team shield and team name on the left, and period, timer, and match controls on the right. The shield stays visible at every phone width; the name truncates rather than widening its panel. The period sits above the time beside the controls; on the narrowest phones, that timing stack moves above the controls rather than reducing their touch targets. All three timing lines share a right edge. Symmetric score columns in both expanded and collapsed headers keep the score separator on the viewport centerline during the transition. The collapsed numbers use fixed 44px columns, so their spacing stays moderate instead of growing with the viewport and leaves more room for the side panels.

## Composition

- Main configuration screens use a single centered ledger column, not nested card grids.
- Ruled dividers structure lists and sections.
- The first-run coach picker is a ruled identity ledger, not a credential form. Each large row leads directly with the coach name, compact team shields, and explicit Head coach / Assistant coach assignments; placeholder initials or profile imagery are omitted until the product has meaningful coach identity data. If a match is active, **Live game** appears only in the matching team assignment line rather than as a coach-wide status. Coaches without access to that active team remain visible for roster stability but become focusable, non-activating rows that name the active team and replace the navigation chevron with an alert icon. The persisted persona appears in the global header as a compact coach switcher using a two-person icon, the current coach name, and a single-line double arrow. It deliberately avoids both a chevron, which would promise a menu, and the stacked substitution glyph.
- While a match is active, the coach picker leads with a turf-tinted recovery strip naming that team. Its danger action requires confirmation, uses the normal finalization path, and opens the completed report with **Return to coaches** rather than silently clearing the match.
- Selecting any coach assigned to the active match reopens that live game immediately, including multi-team coaches; the team picker is not inserted between an authorized coach and the only resumable game.
- Active-game indicators keep a stable turf center dot while a restrained outer halo expands and fades every 1.8 seconds. Reduced-motion mode replaces the loop with the existing static halo.
- Team age badges and pitch position tags behave like removable tactics-board magnets.
- Game setup places a compact, right-aligned team lockup on the same row as **Prepare game**: the team name and `age · format` lead into a 32px shield at the outer edge, while the helper copy spans the full width below. For multi-team coaches, this lockup is a quiet 44px **Change team** control whose metadata line pairs a small single-line double arrow directly with **Change**; the stacked substitution glyph remains reserved for player rotations. Single-team coaches see the same identity without interactivity. No separate back-navigation row is reserved.
- The Sideline mark shows a ball crossing a touchline, combining the match setting with a small flash of substitution orange.
- Goal actions and player goal markers use one shared classic-panel soccer ball drawing with a filled center pentagon and one continuous five-panel seam network. Avoiding detached outer patches keeps the silhouette unmistakably soccer-specific at the 13px pitch-marker size and carries unchanged into the hat-trick marker beneath its top hat.
- Completed-game scorers are ordered by goals, then total playing time, then name so the report immediately surfaces the match's biggest scoring contributions. Hat tricks become a single earned match-sheet flourish: the scorer row receives a restrained warm wash within the normal ledger rules, the existing top-hat balls grow slightly, and a scalloped turf stamp with a warm magnetic-board offset lands beside the player name. The one-time stamp motion is removed under reduced-motion preferences; routine goals and live operational surfaces remain undecorated.
- Once a coach is selected, the top-right header actions begin with a 44px coach switcher that visibly names the current coach and is accessibly labeled **Change coaches**, followed by adjacent Primer `IconButton`s for light/dark mode and settings. On narrow phones, the redundant Sideline wordmark collapses to its mark to preserve breathing room and full-size touch targets. The settings cog opens a conventional anchored Primer ActionMenu in every viewport; it never becomes a bottom sheet. Three clearly explained Primer `ToggleSwitch` controls manage screen wake lock, substitution chime/vibration, and device-persisted **Demo mode**. Helper copy stays static while toggling: **Prevents auto-lock while Sideline is visible during an active game.** and **Notify me when a bench rotation is due.** On/Off is communicated by the toggle itself, not an extra sentence; unsupported-browser and wake-lock failure messages are separate, accessibly associated notes. Their leading icons remain secondary to the text: a daylight/wake symbol for screen lock, a ringing bell for alerts, and a compact blue police-box silhouette for the Time Lord joke in Demo mode. Coach identity and settings are stored separately from game data so they persist without affecting game-state migrations. Demo mode adds one 44px fast-forward icon between Start/Pause and End game in the expanded live header only. At widths up to 760px, demo mode makes all three controls icon-only to preserve phone space. Above 760px, Start/Pause/Resume and End game retain their labels, including when resizing across the breakpoint; fast-forward remains icon-only. Normal mode retains labeled controls. Fast-forward opens a focused dialog whose body begins with a deliberate inset below the header divider, then shows **Current match time**, a labeled positive-minute offset field, and inline errors; the standard footer holds Cancel and a primary action that resolves the destination before commitment, such as **Jump to 15:00** when adding nine minutes at 6:00. Both displayed times use the live header's period-aware match clock, including after earlier added time. The control remains absent for ordinary users, works from either clock state, and pauses automatically after each jump.
- Enabling Substitution alerts previews the real chime and vibration where supported; disabling and restoring the preference do not preview it. Enabling while already due produces one notification, not overlapping preview/due sounds.
- Golden Dragons use a gold-and-turf shield with a bold, front-facing heraldic dragon head: hooked swept horns, an armored brow, a tapered muzzle, and narrow gold negative-space eyes stay unmistakable at header size, while a centered U8 label occupies the clear gold crown above the emblem. Fireballers use an ink shield with an orange flame and ball. Team crests identify squads without replacing text labels.
- The live game expands to a two-column pitch/bench workspace on larger screens and a single scan path on phones.
- Full pitch views read bottom-to-top from the team’s defending goal toward the attacking end. Subtle Attack/Defend labels make that orientation explicit, and formation coordinates keep forwards outside the penalty-area edge while preserving recognizable defensive, midfield, and attacking lines.
- Pitch magnets prioritize outdoor legibility over maximum density. Player names are the strongest and largest text, position codes use compact true-neutral gray tags instead of green-on-green or black-and-white styling, and elapsed time is deliberately smaller and lighter. A queued substitution places its warm crossed-arrows icon in the exact center of the top metadata row, between the left-aligned position and right-aligned playing time, so the state reads as belonging to the whole player card rather than to the position tag. Mobile magnets gain enough height for the larger type while preserving separation in dense 9v9 layouts. Dark-mode cards use a quiet slate boundary rather than the pale text color, preventing a glowing white-box effect, while retaining the same restrained teal field shadow as light mode.
- Successful pitch drag-and-drop uses a brief magnetic-snap confirmation rather than a generic circular success badge: a compact scalloped turf seal lands with a matching warm offset layer, settles into place, and fades without blocking the field. Its center aligns to the pitch card’s top metadata row, fully masking the centered queued-substitution icon when present instead of partially colliding with it at the card midpoint. A centered status notice uses the available pitch width rather than the browser’s half-width absolute-position calculation, keeping ordinary player-name combinations on one line while preserving a safe edge inset. Reduced-motion preferences collapse the authored movement to the existing near-instant confirmation.
- New-game setup uses a linear sequence of three focused panels—Attendance, Formation, and Starters—with one compact current-step progress indicator in the header and persistent destination-labeled Primer controls (for example, Formation or Starters) instead of cramped tabs or one long scrolling form. The fixed mobile footer preserves the standard default and primary button treatments with leading/trailing directional visuals rather than replacing them with custom icon badges. The toolbar contains navigation only and does not repeat progress. Backward and forward controls share the same structure. Attendance remains a two-column touch grid on phones to minimize vertical travel.
- The Starters step reuses the pitch as the primary assignment surface. Large position magnets support direct pointer dragging and retain tap-to-open player pickers. The derived starting bench sits directly below the field in a wrapping tray of single labeled, draggable buttons with 44px minimum touch targets, not separate grips. Touch users hold for 125ms to drag, consistently across starter pitch, starter bench, and live pitch players; moving more than 8px before the hold cancels drag intent so a normal swipe scrolls. A quick tap still selects or opens player actions. Only an activated drag prevents touch scrolling. Mouse/pen dragging needs no hold. A bench selection turns pitch controls into explicit placement actions, with tap-away and Escape as exits. Dropping on an occupied position swaps starters or moves the displaced starter to the bench, atomically.
- Starter warnings use progressive disclosure: a small warm circled-exclamation icon sits on the affected player's pitch marker without changing its dimensions. The entire marker, including the icon, opens the existing starter picker; an associated screen-reader description announces that concerns are available. The picker names the current player and explains only that position's concerns above replacement choices. Missing bench goalkeeper backup is not a starting-lineup concern. No notes panel, sticky guidance, or floating warning prose competes with the pitch. Dragging retains its warm destination outline, pointer-following player name, and polite screen-reader move preview. There is no Cancel selection button: tapping outside a player clears bench selection, tapping another bench player switches selection, and tapping a pitch player places the selected player. Tapping the selected bench player again or pressing Escape also clears selection. Dismissal does not swallow another control's action or change assignments. Starter picker rows show only name, preferences, and current assignment; the header explains bench replacement versus starter swaps once. Arrow-based move breakdowns and reserve warnings are omitted. Pointer cancellation and releases outside real target rectangles leave the lineup intact. A compact Undo control, accessibly named Undo lineup change, sits beside Auto-fill and Reset, avoiding repeated confirmation dialogs during setup.
- Critical live controls sit inside an opaque, edge-to-edge bottom surface with safe-area padding and four equal-width Primer buttons. Content never shows through or around the navigation surface while scrolling.
- The game clock remains sticky below the app header on phones.
- The Game in progress strip on team selection shares the live game’s one-second soccer match-clock cadence, including accurate paused and added-time states.

## Controls

The Starters screen has no goalkeeper-reserve banner or "GK option" labels. Keeper suitability remains in the normal preference list within the player picker. During live play, a compact Primer warning Banner near the rotation controls appears only for an upcoming keeper handoff with no workable rest/replacement plan. It names the action needed without adding a timer, mandatory confirmation, or extra stoppage. Explicit queued choices remain authoritative.

During starter dragging over a valid destination only, position-fit feedback is inset inside the top of the pitch near the opposing goal. It lists the affected players' proposed roles and preference fit without reserve warnings. The feedback does not follow the pointer, intercept pointer events, or occupy layout space; the compact name preview alone stays centered on the pointer. Releasing or cancelling removes both. There is no generic "Drop on..." prompt, nor a feedback panel at rest, during tap selection, or while dragging over empty pitch space.

Drag feedback uses one compact row per affected player, with the dragged player first. The bold name and destination ("Goalkeeper" or "Bench") sit next to each other on the same line; preference fit is a separate right-aligned label ("1st preference", "Not preferred", or "No preferences listed"). Bench destinations and newly open positions do not show a preference label. Long names and labels wrap only when needed rather than truncate. No arrow, colon, or dot-separated sentence combines these distinct facts.

Starter bench players are drop targets when dragging from the pitch, using the same warm outline as pitch destinations. The swap preserves the occupied position and keeps keyboard focus on its incoming player. No extra confirmation or control is introduced.

U8 automatic starter selection quietly considers the last kickoff: previous bench players receive a modest boost alongside position fit and keeper workload. There is no mandatory rotation, new warning, or extra setup step. Manual pickers keep their preference-first order. On both teams, untouched automatic lineups follow attendance using the same solver as Reset plus Auto-fill. After coach edits, attendance changes preserve occupied positions and fill only vacancies by preference; Reset remains the explicit way to rebuild the entire lineup.

Undo and Reset in the starter toolbar use Primer's large invisible-button horizontal padding token, retaining the same inner spacing at rest and on hover. This overrides the legacy padding-free quiet-button treatment only in this toolbar; all three controls retain a minimum 44px touch target and wrap when needed on narrow screens.

Player-level concerns in the starter picker use a compact Primer warning Banner, with 1rem of spacing above and below to separate it from the dialog header and replacement choices.

Starter-picker choices rank the selected position's first-preference matches before second, third, and fourth preferences, then players with no recorded preferences, then non-matches. Names sort alphabetically within each tier. Current starter/bench status stays visible as context without affecting this order; the current occupant is excluded.

The banner title supplies the player and position. Preference warnings positively name the player's recorded preferences, in preference order: "Eli prefers midfield and forward." or "Eli prefers forward, defense, and midfield." Single preferences omit a conjunction. This applies to both outfield and goalkeeper assignments, without repeating the current position or implying playing-history data. Starting both keeper options does not create a warning.

The corresponding pitch marker retains the circled-exclamation icon on the neutral paper background, using Primer's `fgColor-attention` warning color, including its dark-mode equivalent. The picker retains the Primer warning Banner.

Keeper-change notices distinguish preparation from execution. The planner evaluates the selected keeper pair at the next scheduled rotation and names that future context when a warning is needed. The ready checklist evaluates the current clock, labels premature execution **Wait on this rotation**, and describes an incomplete bench turn for a direct bench-to-keeper substitution, not an intentional linked field-to-keeper move. Timing, rest, and atypical-keeper concerns share one compact notice rather than stacked banners. These advisories use Primer's native yellow warning treatment, not the orange substitution colors. The review header owns its divider; the notice sits below it in the scrolling body with 1rem of space above and below, and the checklist does not add a second header-like rule. The notice describes **Send 'em in** for assistive technology without disabling the coach's override, and clears as the live keeper/rest thresholds are met.

Keeper and rest targets allow a practical stoppage window of 20% of the team's normal rotation interval: one minute for a standard 40-minute U8 game and three minutes for a standard 60-minute U12 game. Notices disappear within that window when both conditions are met, rather than asking the coach to wait for an exact second. Nominal keeper targets are twice the reminder interval for both teams and either period format: 10:00 for a standard U8 game and 30:00 for a standard U12 game. Repeat keeper turns and backup keepers' first turns can shorten to one rotation to protect an outfield opportunity and the player's remaining playing budget. Planning and execution notices use the adjusted target, so a recommended five-minute turn does not produce a contradictory ten-minute warning. The reminder schedule and rest requirement remain unchanged, with no extra countdown or control.

Default substitution counts prioritize the rested bench group, using that same forgiving window, rather than silently halving a rotation to close a total-minutes gap. Keeper recommendations honor the existing preference order within rest and total-playing-budget constraints: primary keepers are preferred over backups, with cumulative keeper-time balancing within each rank. Minutes come from actual position history. No extra alarm, setting, or confirmation is added. Outgoing selection preserves keeper preparation when a rested keeper returns outfield, transferring that preparation only to an eligible keeper with no greater cumulative keeper-time band. A short keeper turn prepares its successor in that same handoff batch; keep a reserve back only when no outgoing keeper can provide cover instead. An automatic plan is assessed as a whole before showing live preparation advice; the player previously earmarked for goal is not a permanent reservation, and explicit coach choices stay authoritative.

Live preparation advice never stacks a Primer warning on top of the custom ready/due rotation banner. A genuine concern becomes a full-width text note within the existing warm banner, preserving its countdown and action. Only when no rotation banner is present does preparation use a standalone Primer warning, with 1rem of space above it.

Near full time, a rotation that would leave only the final timing buffer is not presented as due. Status reads **No more scheduled**, without an alert or automatic planner opening. An explicitly opened planner explains that coach-directed changes remain available and starts without suggested pairs; its disabled action says **Choose a swap** until the coach adds a row. Add still suggests that explicitly requested pair; Optimize remains disabled. Existing ready plans keep their Review action and selected players.

Near an intermediate period break, use that same buffer (two minutes for standard U8 games, three for U12) to defer a late scheduled rotation to the break. Status reads **At the break**; the normal warm ready/due banners and automatic alerts yield instead of urging a change for the final few seconds. This quiet-window rule takes precedence over the ordinary ready-banner and alert behavior below. The sticky Review/Create plan control remains accessible, and a manually opened planner explains **Plan for the period break** while retaining fairness suggestions. The period-end banner takes over the saved plan's ready count and review action when regulation time is reached. No plan is discarded or executed automatically, including during added time. Invalid-plan errors remain visible. Planning and keeper-rest projections use the deferred break time; the coach can still execute earlier or during added time.

- Minimum interactive target: 44px; critical controls are 50–66px.
- Conventional commands use Primer `Button` and `IconButton` primitives so focus, disabled, icon, and touch behavior stay consistent. Lucide icons are passed through Primer's `leadingVisual`, `trailingVisual`, and `icon` APIs; Sideline classes retain the established turf, warm, danger, sizing, and layout language. Purpose-built selection surfaces—team rows, attendance tiles, formation cards, tabs, score controls, pitch magnets, player choices, and numeric steppers—remain semantic native buttons because their geometry and state model are not conventional button chrome.
- Adding the final available keeper pairing uses the same Add action, without a separate override link or editing detour. Existing pairings remain protected. Smaller outfield-only plans stay quiet. An early keeper swap shows Primer's compact warning Banner above the rows: a soft yellow surface, warning icon, bold **Early keeper change** heading, and 14px explanation using Primer's native light/dark warning tokens. It is a polite, non-blocking status with no dismiss button or extra actions. When needed, the same banner adds **[Name] does not typically play goalkeeper.** That preference warning remains a plain status line when no timing or rest warning is needed. Neither treatment repeats the row's IN / OUT pairing or adds editing instructions; an on-time change to a rested eligible keeper needs no note. A linked handoff reserves both field participants; Add disappears rather than offering a count that would split it.
- Buttons are square or minimally softened by default. On phones, setup commands use fixed, edge-to-edge bottom surfaces with borderless tap areas, while live controls use large invisible-variant Primer buttons within the same safe-area-aware dock; page content reserves the toolbar height exactly once. Every bottom sheet spans the full viewport width regardless of its desktop maximum, while dialog task and confirmation actions retain the squared, tactics-board button treatment.
- Conventional actions stay within Primer’s default, primary, and danger hierarchy. Primary actions use turf; their disabled state switches to a neutral wash, quiet border, and muted ink instead of fading turf toward a misleading brighter green. Warm orange is reserved for substitution state, warnings, and directional emphasis rather than a separate button variant.
- A successful substitution opens a compact staging sheet with strong IN / OUT direction, Primer `Label` jersey numbers (`success` for IN and `danger` for OUT), and the affected position; numbers stay out of routine live screens to preserve scan speed, while attendance reuses the same semantic pair—success when present, danger when absent—during pregame confirmation.
- Planned substitutions use shared IN / OUT column headings rather than repeating direction labels in every row. The boundary prevents the code from visually merging with the player name, and the accessible name exposes the full position label. This constrained surface compresses hat tricks to one hatted ball plus `×3`; the player-name segment can ellipsize before either the goal total or position Label overflows.
- Every End game action uses the same finish-flag icon. On phones, the expanded action uses standard Primer danger styling, while the collapsed header reduces it to a flag `IconButton` to protect space while retaining a 44px touch target, an explicit accessible name, and a tooltip. The final confirmation keeps **End game** as the filled danger action, pairs it with the default **Continue game** safe action, and includes the standard header close button; Continue, close, Escape, and backdrop dismissal are equivalent.
- End-game confirmations, including coach-picker recovery, reuse the playing-time list when someone is below their actual available-time minimum. They show played minutes and the exact minimum in `m:ss`, explain the late-arrival/time-out adjustment, and explicitly allow finishing when play is over. Their normal safe and finish actions remain unchanged; no second confirmation or mandatory extra play is introduced.
- Confirming **End game** definitively clears the persisted active match before opening a dedicated full-height game-summary page; the summary is a transient completed-game destination, never a resumable live-game state. It resets to the top, leads with the final score, and uses a ruled roster ledger sorted with scorers first and then by playing time. Each player has one bold total followed by plain position/time rows, with a direct zero-time message for players who never entered. Scorers receive one small soccer-ball marker per goal beside their name; goal positions and exact times stay in the game timeline to keep the player ledger calm. The collapsed game-timeline disclosure follows the roster ledger, and a sticky footer provides the single return action without covering report content. That action reads **Prep for next game** for a single-team coach and **Return to teams** for a multi-team coach.
- PWA installation appears as a full-width turf-tinted action beneath coach selection, visible only while running in a browser.
- Form controls use white fill, dark text, and a visible 1px neutral border.
- Focus uses a 3px blue outline with offset.
- Disabled controls retain their label and use reduced opacity.

## Pitch

The pitch is the signature surface. It uses real field markings and restrained mowing stripes. Occupied player magnets use a stable two-row layout with a compact metadata rail at the top and the player name centered beneath. Position remains at top left; once any current playing time diverges, the uninterrupted **Playing** timer remains at top right using the same compact seconds/minute notation as roster rows. The pitch deliberately uses current playing time because it is the immediate rest-and-rotation surface; aggregate **Played** time remains available in the roster rail and player dialogs. A warm reverse-arrows icon appears immediately beside the position code when that player has a pending substitution, preserving the timer while making the next rotation visible at a glance. The redundant visible “playing” label remains omitted inside the magnet. Slightly wider responsive magnets accommodate scorer markers without crowding adjacent 9v9 positions. Nearby helper copy explicitly calls out tap-for-substitution and drag-to-swap. A drop commits only when the pointer is visibly over another magnet, avoiding broad invisible nearest-position zones. Starter and live pitches share a compact name preview centered on the pointer, with no vertical offset or movement lag. It renders outside pitch clipping and ignores pointer events, while the original card stays in its assigned slot at half opacity. Cancellation removes the preview and restores the source without a return animation because the source never moved. A successful live drag briefly highlights both affected player identities, places a checked seal on each magnet, and raises a concise checked confirmation over the pitch. Motion collapses under reduced-motion preferences. A tap opens the same Plan out picker as the On field row. The position editor, opened from the row control, reuses the complete on-field context—position, **Played**, **Playing now**, and conditional next rotation—above the same large, scrollable player-choice rows used by substitution sheets. Destination rows lead with the full position label, followed by a selected checkmark when applicable, place the jersey-numbered occupant beneath it, and keep **Playing / Total** timing at the right; open destinations explicitly read **Unoccupied position**. Selection also uses the established turf row treatment. The rows omit redundant Swap/Move copy. The footer begins as disabled **Choose a position**, then becomes the exact concise operation—**Swap with [player]** or **Move to [position code]**—with a fully explicit accessible name. Empty required positions use a dashed magnet and the word “Open,” making short-sided or injury states impossible to miss.

## Motion and accessibility

The product uses no decorative animation. State changes are immediate. `prefers-reduced-motion` reduces all transitions and animation durations. Semantic headings, labels, buttons, pressed states, dialogs, alerts, keyboard focus, and a skip link are included. Text and controls target WCAG AA contrast.

Every modal surface uses a shared Sideline shell backed by Primer Dialog. Dialogs are centered on larger screens and bottom-aligned at full width on phones, with fixed Sideline-styled headers and action footers around one independently scrolling body. A deep translucent ink backdrop clearly separates the active task from the paused game without hiding useful context. Primer owns focus trapping and restoration, Escape and backdrop dismissal, document scroll locking, viewport constraints, and nested-menu layering. Destructive alert dialogs normally omit the close button when cancellation already has task-specific meaning; the End game confirmation intentionally includes it because continuing the game is an unambiguous safe default, and every dismissal path is equivalent to that action. The Substitution plan dialog is capped at 84% of the viewport so live-game context remains visible; other dialogs use a 92% ceiling so long player lists remain reachable without background drift.

## Responsive rules

- At 760px, pitch and bench stack; the clock becomes sticky.
- At 520px, attendance becomes one column and setup assignments stack their select. Substitution rows retain the desktop IN ↔ OUT sequence using constrained selector columns, compact option text, and a visible directional icon.
- No critical action depends on hover.
